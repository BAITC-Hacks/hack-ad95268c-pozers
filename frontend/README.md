# Frontend ↔ backend

Запускайте из корня проекта в двух терминалах:

```powershell
npm.cmd install
npm.cmd run dev
```

```powershell
npm.cmd run frontend
```

Откройте **http://localhost:4173**. Backend работает на http://localhost:3000.
Не открывайте `index.html` через `file://`: браузерный origin должен совпадать
с разрешённым адресом. Порт frontend по умолчанию 4173.

В корневом `.env` должны быть настроены EKT_USERNAME, EKT_PASSWORD,
OPENAI_API_KEY и при необходимости OPENAI_MODEL. Ключи остаются только
на backend. Опциональные настройки:

```dotenv
FRONTEND_ORIGIN=http://localhost:4173
FRONTEND_PORT=4173
```

При другом порте frontend измените обе настройки и перезапустите оба сервера.
`localhost` и `127.0.0.1` — разные origins; используйте адрес из FRONTEND_ORIGIN.
CORS разрешает один конкретный origin и методы GET/POST, без wildcard.

## Чат и товары

`assistant-service.js` отправляет `{ message }` в `POST http://localhost:3000/api/chat`.
Ответ `{ message, products }` отображается без добавления демо-товаров.
Адаптер преобразует `article → sku`, `quantity → stock`, ID хранит строкой
для DOM. Реальные name, price, image и url сохраняются. Отсутствующий остаток
или цена обозначается как неизвестный, а не нулевой. Отсутствующие фотографии,
характеристики, единицы измерения и сертификаты не выдумываются. Валюта
в ответе API не указана, поэтому отображается числовая цена по каталогу.

`demo-data.js` не загружается страницей и используется только как фикстура
в тестах. При ошибке backend показывается понятное сообщение; автоматического
перехода на демо-ответы нет.

## Серверная корзина

Кнопка товара сначала вызывает `POST /api/cart/proposals`; backend получает detail,
проверяет цену и quantity, затем открывается окно выбора количества. Неизвестный или нулевой
остаток не позволяет добавление. Проверяется целое положительное количество
с учётом уже добавленных единиц. Количество выше остатка блокируется.

До кнопки «Да, добавить» корзина не меняется. Отмена/Escape отменяет предложение и закрывает окно.
Повторное подтверждение не дублирует товар. После подтверждения корзина
и счётчики обновляются через `GET /api/cart`. Её можно открыть ссылкой в шапке; позиции удаляются на сервере.

Это корзина в памяти backend: она сохраняется при обновлении страницы в той же
cookie-сессии, очищается при перезапуске backend. Сессия живёт 24 часа без активности,
предложение — 30 минут. Cookie передаётся с `credentials: 'include'`. Корзина не меняет
настоящую корзину ekt.kz, не резервирует остатки и не оформляет заказ.
Удалённый остаток может измениться после проверки. Поиск ограничен первыми
3 страницами каталога; его кэш — 3 минуты. AI работает без истории диалога.

## Проверки

```powershell
npm.cmd test
```

62 backend-теста и 27 frontend-проверок с замоканными внешними API.
Проверяются адаптер, CORS, ошибки, подтверждение и остатки. API-кредиты не нужны.

Живой браузерный сценарий требует работающих серверов, ключа OpenAI и
установленного Microsoft Edge. Используется `playwright-core` без скачивания
отдельного браузера. Этот сценарий расходует реальные API-кредиты:

```powershell
npm.cmd run test:browser
```

Для установленного Chrome можно перед запуском указать:
`$env:BROWSER_CHANNEL = 'chrome'`.

При интеграционной проверке в Edge сценарий прошёл: реальный запрос
«Есть Legrand 40A?» вернул товары 515279 и 515283; для 515279 остаток был 36.
До подтверждения корзина оставалась пустой, ввод выше остатка блокировался,
после подтверждения в корзине было 2 единицы. XYZ123NOTFOUND вернул пустой
массив. Проверены desktop и ширина 390px, ошибок JavaScript не было.
Эти значения — результат конкретной проверки, данные каталога могут меняться.
Если выбранный товар распродан, живой сценарий честно завершится ошибкой,
не подменяя его тестовыми данными.

## Ревизор закупки

На том же http://localhost:4173 откройте вкладку «Ревизор закупки».
Редактор, строки результата, выбор, итог и копирование вопросов адаптированы
из `ekt-frontend/public/revisor.js`. Отдельный сайт и demo backend не нужны.

Вставьте, например:

```text
200300273_ ; 2
310100080_ ; 5
XYZ123NOTFOUND ; 3
```

«Проверить список» вызывает реальный `POST /api/audit`. Отображаются артикул,
название, запрошенное количество, остаток, цена и статус каждой строки.
Выбрать можно только `ready`. Неизвестный остаток — `unknown`/`null`, а не 0.
Если есть кандидаты на замену, они показаны отдельно с предупреждением:
совместимость требует проверки. Автоматической замены товара нет.

После выбора нажмите «Подготовить добавление». В групповом окне проверьте
список и нажмите «Да, добавить». До этого корзина не меняется.
Остатки проверяются при подготовке и повторно при подтверждении; при нехватке
любой позиции ничего из пакета не добавляется. Дубли учитываются суммарно.
Цена изменилась — отмените и подготовьте предложение снова.
Редактирование списка/изменение корзины сбрасывает старый результат.

Ограничения: до 10 строк; первые 3 страницы каталога; целое количество без
выдуманных единиц измерения. Корзина общая с чатом, хранится на сервере прототипа,
не связана с реальной корзиной ekt.kz. Товары, цены и остатки при этом реальные.
Обновлённый `test:browser` проверяет и чат, и Revisor в одном интерфейсе.
