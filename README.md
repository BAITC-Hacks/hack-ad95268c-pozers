# hack-ad95268c-pozers
Hackathon team repository for Pozers

## Backend

Минимальный сервер на Node.js и Express. Нужен Node.js 22 или новее.

Установите зависимости:

```sh
npm install
```

Скопируйте `.env.example` в `.env`. В PowerShell:

```powershell
Copy-Item .env.example .env
```

Переменная `PORT` задаёт порт сервера (по умолчанию `3000`). Настоящие ключи
в примере отсутствуют, а `.env` исключён из Git.

Запустите сервер:

```sh
npm start
```

Или запустите режим разработки с автоматическим перезапуском при изменении кода:

```sh
npm run dev
```

Используйте один режим запуска за раз. Для остановки нажмите `Ctrl+C`.

Откройте http://localhost:3000/api/health — сервер вернёт:

```json
{ "ok": true }
```

Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd install`,
`npm.cmd start` и `npm.cmd run dev` вместо соответствующих команд `npm`.

## Каталог ekt.kz

В локальном `.env` заполните выданные организаторами данные Basic Auth:

```dotenv
EKT_USERNAME=
EKT_PASSWORD=
```

Не публикуйте `.env` и не вставляйте пароль в исходный код. Если `.env` уже
существует, добавьте строки вручную, не перезаписывая файл из примера.
Значения с символом `#` заключайте в кавычки. После изменения `.env`
перезапустите сервер.

Откройте http://localhost:3000/api/products или
http://localhost:3000/api/products?page=2. Сервер обращается к
`https://ekt.kz/api/products` с Basic Auth и передаёт параметр `page`, если он
указан. Ответ JSON возвращается без переименования полей и изменения структуры.
Страницы запрашиваются по одной; `page` должен быть целым положительным числом.

Ошибки возвращаются в объекте `error` с полями `code` и `message`:

- HTTP 400: неверный `page`.
- HTTP 503: не заполнены данные доступа.
- HTTP 502: ошибка каталога, соединения или некорректный JSON. При получении
  HTTP-ответа каталога его статус доступен в `error.upstreamStatus`.
- HTTP 504: время ожидания каталога превысило 15 секунд.

Тело ошибки внешнего API, пароль и заголовок авторизации не выводятся в ответ
или в консоль. Структуру товаров нужно смотреть в успешном ответе с действующим
доступом; предположений о полях каталога в коде нет.

Локальные тесты без обращения к ekt.kz: `node --test`.

## API чата

`POST /api/chat`, заголовок `Content-Type: application/json`:

```json
{ "message": "цена ярп4520" }
```

В ответе: `intent`, `reply`, `products`, `pendingAction`. Распознаются поиск,
цена, наличие, характеристики, аналоги и добавление. Поиск сравнивает артикул
целиком или ищет подстроку в названии, без учёта регистра. Для названия с
командными словами используйте кавычки. Это обработка по правилам, без AI.

Для характеристик и наличия запрашивается `url_api_detail`: используются
реальные `description`, `properties`, `quantity`, `stores`. Валюта не
додумывается. Для аналогов и сертификатов подтверждённых данных пока нет:
ответ — «Информация не найдена в каталоге».

Поиск просматривает страницы последовательно (до 20 страниц; после 15 секунд
новая страница не запрашивается, текущий запрос может занять ещё до 15 секунд).
Кэш страниц действует 60 секунд. При достижении ограничения ответ содержит
`searchComplete: false` и пояснение `note`: это не доказательство отсутствия
товара во всём каталоге. Точный артикул завершает поиск сразу. В ответе не
более 10 совпадений; если их несколько, нужно уточнить артикул.

Выбранный товар и pending action хранятся в памяти сервера 30 минут, отдельно
для каждой сессии. Клиент должен сохранять cookie `chat_session` и отправлять
его в следующих запросах. После перезапуска контекст теряется. Без выбора
товара команда «добавь 2 штуки» попросит название или артикул.

После выбора одного товара сообщение `{"message":"добавь 2 штуки"}` возвращает
вопрос и `pendingAction` вида:

```json
{ "action": "confirm_add_to_cart", "productId": 123, "quantity": 2 }
```

Здесь `123` — условный пример: сервер использует ID найденного товара.
Корзина не изменяется. Даже сообщение «да» пока не выполняет добавление:
операции корзины и выполнение подтверждённых действий ещё не реализованы.
Поддерживается только одно ожидающее действие на сессию; новое сообщение
заменяет или отменяет его. Другой пользователь не получает этот контекст.

Проверка из PowerShell с сохранением cookie:

```powershell
$body = @{ message = 'цена ярп4520' } | ConvertTo-Json
Invoke-RestMethod http://localhost:3000/api/chat -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body)) -SessionVariable chatSession
$body = @{ message = 'добавь 2 штуки' } | ConvertTo-Json
Invoke-RestMethod http://localhost:3000/api/chat -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body)) -WebSession $chatSession
```

Пустой или неверный `message` даёт HTTP 400, слишком большой JSON — 413.
Ошибки ekt.kz возвращаются с безопасным описанием, а не маскируются под
отсутствие товара.
