# hack-ad95268c-pozers
Hackathon team repository for Pozers

## Backend

Минимальный сервер на Node.js и Express. Нужен Node.js 22 или новее.

Установите зависимости:

```sh
npm install
```

Скопируйте `.env.example` в `.env`. В PowerShell:

```powershell
Copy-Item .env.example .env
```

Переменная `PORT` задаёт порт сервера (по умолчанию `3000`). Настоящие ключи
в примере отсутствуют, а `.env` исключён из Git.

Запустите сервер:

```sh
npm start
```

Или запустите режим разработки с автоматическим перезапуском при изменении кода:

```sh
npm run dev
```

Используйте один режим запуска за раз. Для остановки нажмите `Ctrl+C`.

Откройте http://localhost:3000/api/health — сервер вернёт:

```json
{ "ok": true }
```

Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd install`,
`npm.cmd start` и `npm.cmd run dev` вместо соответствующих команд `npm`.

## Каталог ekt.kz

В локальном `.env` заполните выданные организаторами данные Basic Auth:

```dotenv
EKT_USERNAME=
EKT_PASSWORD=
```

Не публикуйте `.env` и не вставляйте пароль в исходный код. Если `.env` уже
существует, добавьте строки вручную, не перезаписывая файл из примера.
Значения с символом `#` заключайте в кавычки. После изменения `.env`
перезапустите сервер.

Откройте http://localhost:3000/api/products или
http://localhost:3000/api/products?page=2. Сервер обращается к
`https://ekt.kz/api/products` с Basic Auth и передаёт параметр `page`, если он
указан. Ответ JSON возвращается без переименования полей и изменения структуры.
Страницы запрашиваются по одной; `page` должен быть целым положительным числом.

Ошибки возвращаются в объекте `error` с полями `code` и `message`:

- HTTP 400: неверный `page`.
- HTTP 503: не заполнены данные доступа.
- HTTP 502: ошибка каталога, соединения или некорректный JSON. При получении
  HTTP-ответа каталога его статус доступен в `error.upstreamStatus`.
- HTTP 504: время ожидания каталога превысило 15 секунд.

Тело ошибки внешнего API, пароль и заголовок авторизации не выводятся в ответ
или в консоль. Структуру товаров нужно смотреть в успешном ответе с действующим
доступом; предположений о полях каталога в коде нет.

Локальные тесты без обращения к ekt.kz: `node --test`.

## Поиск и детали товаров (этап 3)

`GET /api/products/search?q=Legrand` возвращает `{ query, count, items }`.
`count` — количество найденных товаров в просмотренной части каталога.
Объекты `items` сохраняют поля реального API, в том числе `id`, `name`,
`article`, `price`, `image`, `url`, `url_api_detail`, `offers`.

Приоритет результатов: точный артикул, подстрока артикула, подстрока названия.
Сравнение без учёта регистра. При отсутствии совпадений возвращаются
`count: 0` и `items: []`. Отсутствующий, пустой, повторённый `q` или запрос
длиннее 200 символов даёт HTTP 400 с кодом `INVALID_SEARCH_QUERY`.

**Ограничение прототипа:** поиск проверяет только первые 3 страницы каталога.
В проверенном ответе списка есть `page`, `per_page`, `count`, `items`, но нет
общего количества страниц. `count` не трактуется как размер всего каталога.
При пустой или неполной странице загрузка заканчивается раньше.
Отсутствие совпадений не означает отсутствия товара во всём каталоге.

Загруженная часть каталога хранится в памяти 3 минуты; повторные и одновременные
поиски используют общий кэш/общую загрузку. Первая загрузка и обновление
делают максимум 3 запроса к ekt.kz. При ошибке возвращается ошибка API,
а не пустой результат. Кэш теряется при перезапуске; цены могут отставать
на время его действия. Эти ограничения относятся к новому GET-поиску.

`GET /api/products/515279` возвращает исходный detail JSON из
`https://ekt.kz/api/products/detail?id=515279` без переименования полей.
Детали запрашиваются напрямую, даже если товар не входит в первые 3 страницы.
Неверный формат ID даёт HTTP 400; HTTP 404 ekt.kz преобразуется в HTTP 404
с кодом `PRODUCT_NOT_FOUND`. Другие ошибки ekt.kz возвращаются как 502/504
с безопасным описанием; HTTP-статус внешнего API, если получен, находится
в `error.upstreamStatus`.

В реальном detail товара `515279` обнаружены поля:
`id`, `name`, `article`, `description`, `price`, `quantity`, `stores`,
`image`, `url`, `offers`, `properties`.

- Характеристики: `properties`, например `KOLICHESTVO_POLYUSOV`,
  `NOMINALNYY_TOK`, `NOMINALNOE_NAPRYAZHENIE`; описание — `description`.
- Количество: `quantity` (при проверке 36, значение может меняться).
- Склады: `stores`, элементы с `id`, `name`, `quantity`.
- В проверенном товаре сертификатов и ссылок на документы не обнаружено.
  Это не утверждение об отсутствии документов у всех товаров каталога.

Для проверки откройте:

- http://localhost:3000/api/health
- http://localhost:3000/api/products
- http://localhost:3000/api/products?page=2
- http://localhost:3000/api/products/search?q=Legrand
- http://localhost:3000/api/products/search?q=310100080_
- http://localhost:3000/api/products/515279

Все тесты: `node --test`.

## AI-ассистент (этап 4)

Добавьте в существующий локальный `.env`, сохранив настройки ekt.kz:

```dotenv
OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.6-luna
```

Вставьте настоящий ключ только в `.env`. Файл исключён из Git.
Модель читается из `OPENAI_MODEL`; если значение пустое — `gpt-5.6-luna`.
Без ключа сервер и маршруты каталога работают, но чат отвечает HTTP 503
с кодом `OPENAI_NOT_CONFIGURED`. После заполнения перезапустите
`npm.cmd run dev`. Установка зависимостей: `npm.cmd install`.

`POST /api/chat`, `Content-Type: application/json`:

```json
{ "message": "Есть автомат Legrand 40A?" }
```

Успешный ответ содержит только `message` (русский текст) и `products`
(карточки использованных товаров). Карточки собирает сервер из реальных
полей `id`, `name`, `article`, `price`, `quantity`, `image`, `url`.
Отсутствующие поля не добавляются. Пустой/неверный `message` или текст
длиннее 2000 символов даёт HTTP 400. Слишком большой JSON — HTTP 413.

Используется официальный пакет `openai` и Responses API. Инструменты:

- `search_products({ query })` напрямую вызывает существующий поиск.
  GET-поиск и чат используют один кэш: первые 3 страницы, срок 3 минуты.
- `get_product_detail({ id })` напрямую вызывает `getProductById`.
  Допустим только ID из результатов поиска или сообщения пользователя.

Модель выбирает инструменты, подходящие ID и нужные поля ответа через
строгую JSON-схему. Свободный текст модели не передаётся пользователю:
сервер составляет русский ответ из реальных данных. Это ограничивает стиль
ответов, зато AI не может подставить собственную цену, остаток или название.
Факты из `quantity`, `stores`, `properties`, `description` требуют detail;
если AI пропустил этот вызов, сервер получает detail перед ответом.
Характеристики выводятся с исходными кодами свойств API. Валюта не угадывается.
Несколько выбранных товаров сопровождаются просьбой уточнить артикул.
Выбор релевантных вариантов делает модель; после добавления ключа его нужно
проверить на реальных запросах. Ложный ID или ответ без каталога отклоняется.

Если товара нет: «Не удалось найти подходящий товар в доступной части каталога.»
Если данных не хватает: «В полученных данных эта информация не указана.»
Подтверждённого поля сертификатов пока нет — наличие сертификата не утверждается.

Один запрос ограничен 7 обращениями к модели и 10 вызовами инструментов;
ожидание одного OpenAI-запроса — до 20 секунд, бюджет AI-цикла — 90 секунд
(начатый запрос каталога может завершиться позже). Повторы SDK отключены.
HTTP 502/503 сообщает об ошибке OpenAI безопасным текстом, без исходного
тела ошибки, ключей и stack trace. Ошибки каталога сохраняют свой статус.
В OpenAI отправляются текст запроса и данные товаров, без EKT-авторизации.
Сохранение Responses отключено через `store: false`; логирование SDK отключено.

Чат обрабатывает каждый запрос отдельно, без истории и cookie-сессий.
Старый чат по правилам и pending actions заменены новым API.
Frontend подключён к этому API; серверная корзина изменяется только после
явного подтверждения. Оплата, заказы и загрузка файлов не реализованы.

Проверка из PowerShell (UTF-8 сохраняет кириллицу):

```powershell
$messages = @(
  'Есть Legrand 40A?',
  'Сколько осталось товара с артикулом 310100080_?',
  'Какие характеристики у товара 515279?',
  'Расскажи про несуществующий товар XYZ123NOTFOUND'
)
foreach ($message in $messages) {
  $body = @{ message = $message } | ConvertTo-Json
  Invoke-RestMethod http://localhost:3000/api/chat -Method Post -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body)) | ConvertTo-Json -Depth 10
}
```

Все автоматические тесты: `npm.cmd test`. OpenAI и ekt.kz в них замоканы;
реальные API-кредиты не расходуются. Живая проверка AI требует ключа.

Реализация сверена с [официальной документацией function calling](https://developers.openai.com/api/docs/guides/function-calling),
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
и [моделью GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna).

## Запуск интеграции

Из корня проекта: `npm.cmd install`, затем `npm.cmd run dev` для backend.
Во втором терминале: `npm.cmd run frontend`.
Откройте **http://localhost:4173**.

CORS разрешает адрес из `FRONTEND_ORIGIN` (по умолчанию
`http://localhost:4173`); порт frontend задаёт `FRONTEND_PORT` (по умолчанию
4173). При смене порта согласуйте обе настройки в `.env` и перезапустите
серверы. Frontend отправляет сообщения на `http://localhost:3000/api/chat`.

Результаты AI и товары берутся из backend, без демо-подмены. Перед выбором
количества серверное предложение обновляет detail товара. Добавление происходит
только после кнопки «Да, добавить». Корзина хранится на backend в cookie-сессии,
сохраняется при обновлении страницы, не связана с корзиной ekt.kz и не резервирует товары.

Тесты: `npm.cmd test` — 62 backend и 27 frontend-проверок без платных API.
`npm.cmd run test:browser` — отдельная живая проверка в установленном Edge;
требует запущенных серверов и расходует реальные OpenAI-кредиты.
Подробности и результаты браузерного сценария — в [frontend/README.md](frontend/README.md).

## Ревизор закупки в едином интерфейсе

На **http://localhost:4173** доступны вкладки «AI-чат» и «Ревизор закупки»
с общей серверной корзиной. Каталог использует реальный API ekt.kz, AI-чат —
OpenAI; Revisor обращается к ekt.kz через существующие функции backend,
без вызова AI. Для запуска нужны только два процесса из корня проекта:

```powershell
npm.cmd run dev
```

Во втором терминале:

```powershell
npm.cmd run frontend
```

Папка `ekt-frontend/` оставлена как reference-код второго участника; отдельно
запускать её не нужно. В `frontend/revisor.js` перенесены структура проверки
строк, выбор позиций, сводка суммы, сброс результата при редактировании и
копирование вопросов для уточнения. Навигация и стили адаптированы из
`ekt-frontend/public/`. Исходный `server-demo.mjs`, синтетический каталог,
DEMO-артикулы, demo diagnostics и учебные ответы не используются основным
приложением.

`POST /api/audit` принимает:

```json
{ "text": "200300273_ ; 2\n310100080_ ; 5\nXYZ123NOTFOUND ; 3" }
```

Не более 10 непустых строк; формат — `артикул или название ; количество`.
Количество — положительное безопасное целое число, без единиц измерения.
Текст ограничен 6000 символами и общим лимитом JSON-запроса 8 КБ.
Пустой список/превышение лимита строк даёт HTTP 400. Нераспознанная строка
не мешает проверке других строк. Точный артикул имеет приоритет; при
нескольких совпадениях нужно уточнение, случайный товар не выбирается.

Ответ `{ rows, data_mode: "live", message }` содержит исходную строку `raw`,
запрошенное `quantity`, товар `product` и массив `alternatives`.
`product.sku` берётся из `article`, `product.stock` — из detail `quantity`.
Неизвестные остаток/цена возвращаются как `null`, не как ноль.
Единицы измерения и характеристики не додумываются.

| Статус строки | Значение |
| --- | --- |
| `ready` | Товар найден, количества достаточно. |
| `shortage` | Остаток меньше потребности. |
| `out_of_stock` | Реальный остаток равен 0. |
| `not_found` | Товар не найден в просмотренной части каталога. |
| `unparsed` | Неверный формат или неоднозначный поиск; нужно уточнение. |
| `unknown` | Товар найден, но остаток не указан. Выбор запрещён. |

Повторяющиеся товары проверяются по суммарной потребности списка. В detail
каждый ID запрашивается один раз за проверку. Ошибка API возвращается как
ошибка запроса, а не маскируется под отсутствие товара.

Ограничения поиска прежние: первые 3 страницы, кэш списка на 3 минуты;
detail запрашивается заново. Для shortage/out_of_stock возможны до двух
кандидатов на строку при совпадении реально указанных марки, номинального
тока и числа полюсов; известное различие напряжения исключает кандидата.
На весь список допускается не более четырёх дополнительных detail-запросов
для кандидатов. Это ограниченный поиск, не подтверждение совместимости.
Если оснований недостаточно — `alternatives: []`. Для добавления кандидата
нужно проверить его характеристики и отдельно проверить его артикул.

Выбор доступен только для `ready`, по умолчанию ничего не выбрано.
Проверка списка и выбор строк корзину не меняют. Кнопка «Подготовить добавление»
заново получает detail и открывает одно групповое подтверждение с товарами,
количествами и суммой. После нажатия «Да, добавить» остатки ещё раз
проверяются, с учётом уже добавленного в корзину. Если хотя бы одной позиции
не хватает — весь пакет блокируется. При изменении цены нужно подготовить
предложение заново. Отмена и повторный клик не приводят к добавлению дублей.

Корзина хранится **в памяти backend, отдельно для каждой сессии**,
сохраняется при обновлении страницы, не резервирует остатки, не оформляет заказ и
**не изменяет настоящую корзину ekt.kz**. Остатки магазина могут измениться
после запроса; атомарного резервирования во внешнем магазине нет.

Проверки выполнены: 62 backend + 27 frontend тестов основного проекта.
Существующие тесты не удалены. Дополнительно прошли 28 тестов reference-проекта
(`npm.cmd --prefix ekt-frontend test`) и его проверка синтаксиса.
Отдельный legacy-стенд `ekt-frontend/tests/browser-components.py` не входит
в основной запуск: перенесённый UI проверяется живым `npm.cmd run test:browser`.
Браузерный сценарий проверил старый чат, оба раздела, реальные ready/not_found,
отмену, явное подтверждение и запрет превышения остатка, а также ширину 390px.
При проверке товара 515279 API вернул цену 26930 и остаток 36; эти данные могут
измениться. `.env` игнорируется Git; секреты во frontend не передаются.

## Серверная корзина

Новые маршруты работают через cookie `ekt_cart_session` (HttpOnly, SameSite=Strict,
Secure при HTTPS). В браузере запросы корзины отправляются с `credentials: 'include'`.
CORS разрешает cookie только точному `FRONTEND_ORIGIN`; настройки ключей не меняются.
Открывайте frontend и backend через один hostname, например `localhost`.

| Маршрут | Тело POST / результат |
| --- | --- |
| `GET /api/cart` | `{ items, totalCount, totalPrice }` — текущая корзина. |
| `POST /api/cart/proposals` | `{ "productId": 515279, "quantity": 2 }` → предложение с `proposalId`, `items`, `status`, `expiresAt`. Корзина не меняется. |
| `POST /api/cart/confirm` | `{ "proposalId": "..." }` → подтверждение и корзина. Повтор того же ID не добавляет повторно. |
| `POST /api/cart/cancel` | `{ "proposalId": "..." }` → отмена. Подтвердить отменённое предложение нельзя. |
| `POST /api/cart/remove` | `{ "productId": 515279 }` → удаление для существующей кнопки «Удалить». |

Групповое окно использует тот же `/proposals` с `{ "items": [{ "productId": 515279,
"quantity": 2 }] }` (до 10 позиций). Весь пакет подтверждается или отклоняется целиком.
`items[].quantity` — количество в корзине/предложении; `items[].product.quantity` —
последний полученный остаток ekt.kz. Данные карточки и цена берутся только из detail.

Остаток проверяется при создании предложения и повторно перед первым confirm,
с учётом уже добавленного. Невалидное количество даёт HTTP 400; недостаточный или
неизвестный остаток, изменение цены — HTTP 409. Ошибки ekt.kz не меняют корзину.
Операции одной сессии выполняются последовательно, включая параллельные confirm.
После подтверждения frontend отдельно загружает `/api/cart`; при неопределённом
сетевом результате повторяет тот же `proposalId`.

Хранилище in-memory: **перезапуск backend (включая watch-перезапуск при правке кода)
очищает корзины**. Сессия истекает через 24 часа без обращения к корзине, предложение —
через 30 минут. Прототип рассчитан на один процесс backend: до 1000 сессий,
100 товаров в корзине и 100 предложений на сессию за 30 минут. Это не корзина ekt.kz
и не резервирование товара во внешнем магазине.

Ручная проверка: запустите `npm.cmd run dev` и `npm.cmd run frontend`, откройте
http://localhost:4173, найдите товар, выберите количество. До «Да, добавить» и после
«Отмена» корзина не меняется. После подтверждения обновите страницу: товар остаётся.
Количество больше остатка должно блокироваться; кнопка корзины загружает её актуальное состояние.

Проверка API в PowerShell (cookie сохраняется в объекте, его не нужно выводить):

```powershell
$basket = Invoke-RestMethod http://localhost:3000/api/cart -SessionVariable cartSession
$proposal = Invoke-RestMethod http://localhost:3000/api/cart/proposals -Method Post -WebSession $cartSession -ContentType 'application/json' -Body '{"productId":515279,"quantity":2}'
Invoke-RestMethod http://localhost:3000/api/cart -WebSession $cartSession
$confirmation = @{ proposalId = $proposal.proposalId } | ConvertTo-Json
Invoke-RestMethod http://localhost:3000/api/cart/confirm -Method Post -WebSession $cartSession -ContentType 'application/json' -Body $confirmation
Invoke-RestMethod http://localhost:3000/api/cart -WebSession $cartSession
```

Повторите последний confirm: количество не увеличится. Для проверки отмены создайте
новое предложение и вместо `/confirm` вызовите `/cancel` с его `proposalId`.
