# Фактически выполненные проверки v2.0.0

## Сервер

`npm run check` — проверка синтаксиса всех исполняемых JS-модулей.
`npm test` — 28 тестов, 28 прошли. Фактический вывод: `reports/node-tests.txt`.
18 тестов сохранены из предыдущей версии, добавлены 10.
Одно из новых испытаний запускает полный демонстрационный набор из 12 сценариев.

`npm run demo:checks` выполняет настоящие HTTP-запросы к создаваемым для тестов
локальным серверам, получает JSON и проверяет утверждения через `node:assert`.
`reports/check-report.json` хранит run_id, точные времена, ожидания, наблюдения и трассы
отдельного запуска: 12 из 12. В интерфейсе этот файл не используется как готовый ответ:
кнопка выполняет новый набор и показывает новый run_id.

Проверяются источник/цена/остаток, таблица аналогов, демонстрационные условия,
отсутствие добавления без подтверждения, отрицание «да, но не добавляй», успешное
подтверждение, отказ при превышении остатка, отмена, пять параллельных подтверждений,
чужая сессия, изменение цены/остатка в списке и посторонняя команда во входном списке.
В дополнительных тестах есть CSRF, Origin, лимиты, дубли, вложенная идемпотентность,
неизвестные поля, атомарность списка, отключение и изоляция диагностического стенда.

Это проверки одного процесса на синтетическом каталоге. Нагрузочных проверок
или обращений к сервисам ekt.kz, другим командам и сети хакатона не проводилось.

## Браузерные компоненты

`tests/browser-components.py` — воспроизводимый дополнительный стенд
(Python, Playwright и Chromium; не нужны для обычного запуска приложения).
При работающем `npm start` выполните `python tests/browser-components.py`.
Путь к Chromium можно задать через `CHROMIUM_PATH`.

Ограничение окружения: навигация браузера по URL заблокирована, установка другого
браузера также недоступна. Поэтому использованы загрузка HTML/CSS/JS в память
браузера и тестовый транспорт к реальному локальному HTTP-серверу.
ES-модули объединены без изменения их функций. Тестовая обвязка предоставляет
fetch, базовый URL и генератор UUID. Cookies сессии держит тестовый HTTP-клиент.

**Это компонентная интеграционная проверка, не end-to-end проверка развёртывания.**
Не проверены browser-cookie, CSP/CORS в браузере, HTTPS, настоящая навигация по ссылке,
тайм-аут/потеря ответа через нативный fetch, поведение реального телефона и Safari.
Серверные сценарии CSRF/Origin проверены отдельно прямыми HTTP-тестами.

25 проверок пройдены, список и точное время — `reports/browser-components.json`.
Проверены чтение источников, таблица различий, явный выбор кандидата,
сброс отчёта при изменении списка/корзины, подтверждение двух позиций,
отрицание и точная текстовая команда подтверждения, реальные результаты стенда,
отсутствие изменения корзины покупателя диагностикой.
На 320 и 390 пикселях у всех четырёх экранов нет горизонтального переполнения страницы.
У таблицы сравнения есть собственная горизонтальная прокрутка.

Снимки интерфейса в `previews/` сделаны в этом компонентном стенде, не на настоящем ekt.kz.

## Что проверить команде в обычном Codespaces

Запустить `npm start`, открыть порт, проверить загрузку ES-модулей и отсутствие ошибок консоли.
Повторить сценарий от списка до корзины, реально нажать ссылку на неё, обновить страницу.
Проверить отмену, повтор клика, прерывание соединения и восстановление результата.
При подключении другого backend снова выполнить весь набор и проверить границы доступа.
Не переносить цифры этого отчёта на новую интеграцию без повторного измерения.
