# EKT Ревизор · версия 2

**Не просто ответ, а проверяемая закупка:** что можно подготовить, чего не хватает,
что требует уточнения и почему.

## Сначала прочитайте это

Это обновление предыдущей папки `ekt-frontend`, не отдельный второй проект.
**Каталог ekt.kz, настоящая корзина магазина и AI НЕ подключены.**
Все шесть товаров, цены, остатки и условия — вымышленные, интерфейс показывает `demo`.
Формат API предложен для согласования с backend-командой, не выдан ekt.kz.
Этот архив не следует выдавать за полностью выполненный кейс хакатона.

## Запуск

Из папки `ekt-frontend`:

```bash
npm start
```

Локальный адрес: `http://localhost:3000`. В Codespaces откройте приватный порт 3000.
Если терминал находится на уровень выше, сначала выполните `cd ekt-frontend`.
Нужен Node.js 22 или новее. Для запуска нет внешних npm-зависимостей, Python не нужен.
Не открывайте `index.html` отдельно: интерфейсу нужен сервер. Обычные GitHub Pages
не запускают этот Node-сервер.

Проверки:

```bash
npm run check
npm test
npm run demo:checks
```

## Что нажать

Откройте «Проверить список», оставьте учебный пример и нажмите «Проверить список».
Раскройте источник у первой позиции, а затем сравнение у DEMO-004.
Выберите только нужные строки и нажмите «Подготовить предложение».
В чате появятся точные товары, количество и сумма. Корзина ещё не менялась.
Подтвердите кнопкой или введите **ровно** `да, добавь`.
`да, но не добавляй` не является подтверждением.

В разделе «Проверки защиты» доступны три запуска:
**12 проверок**, **Подтвердить ×5**, **Показать отказ**.
Результатов до запуска нет. Раскрывающиеся строки показывают ожидание,
полученный результат и HTTP-трассу. JSON можно скачать.

## Как объединены идеи

| Идея | Реализация |
|---|---|
| Ревизор всей закупки | До 10 строк: `DEMO-001 ; 10 шт.`. Готовые, дефицитные, неизвестные и нераспознанные строки показываются отдельно |
| Видимые основания ответа | Раскрываемые `source`, `fetched_at`, `data_mode`, поля и ограничения |
| Живой чек-репорт | Настоящие HTTP-запросы к отдельному локальному экземпляру демосервера |
| Показательный отказ | 20 шт. уже в корзине, ещё 5 при остатке 24 → 409, остаётся 20 |
| Идемпотентность | 5 одновременных подтверждений одного предложения → одна запись; повтор с новым request_id также не удваивает товар |
| Параметры аналогов | Таблица совпадений, различий и неизвестных полей; C→B не объявляется совместимой заменой |
| Дисциплина объёма | Без голосового режима, админки, собственной модели и многоагентной системы |
| Честные результаты | Фактические отчёты и ограничения; нет обещания «0% ошибок» |
| Нерешённые вопросы | Текст для менеджера можно скопировать, но он не отправляется автоматически |

### Важные детали

Проверка списка не изменяет корзину. Дубли одного артикула суммируются.
Метры не конвертируются в штуки. Неизвестный остаток — не ноль.
Частично доступное количество не подменяет запрошенное. Замена выбирается явно.
Любой неизвестный монтаж означает, что совместимость не подтверждена.

Редактирование исходного списка или изменение корзины сбрасывает предыдущую проверку.
Перед добавлением сервер ещё раз проверяет весь список. Если одна позиция не проходит,
**ничего** из этого предложения не добавляется. Цены определяет сервер, не браузер.
При потере ответа успех не показывается, повтор использует тот же идентификатор.

`fetched_at` в этой версии — момент чтения учебных данных на сервере.
Это **не** время обновления ekt.kz. Повтор ранее выполненного запроса сохраняет исходное время.
В неизвестном/неподкреплённом сообщении отсутствие источника показывается явно.
Метка источника — не цифровая подпись и не гарантия правильности данных.

## Архитектура

```text
Интерфейс → public/api.js → server-demo.mjs
                              ├─ учебный каталог + lib/revisor.mjs
                              ├─ предложения и корзины в памяти
                              └─ checks/run-checks.mjs
                                  └─ отдельные временные локальные серверы
```

`public/app.js` — чат, подтверждение, корзина, навигация.
`public/revisor.js` — список, сравнение и экран проверок.
`public/evidence.js` — единое отображение источников и параметров.
`public/api.js` — обращения к API и проверка структуры ответов.
`lib/revisor.mjs` — чтение данных, строгий разбор списка, сравнение.
`checks/run-checks.mjs` — исполняемые сценарии, без произвольной внешней цели.

Сессия использует HttpOnly-cookie, изменяющие запросы — CSRF-токен.
Для развертывания за HTTPS-прокси параметры cookie нужно отдельно проверить.
Учебный сервер рассчитан на приватный локальный стенд / приватный Codespaces.
Стенд можно отключить переменной `DEMO_DIAGNOSTICS=off`.
Не переносите диагностический HTTP-маршрут в production.

## Фактическая проверка этой версии

В `reports/node-tests.txt` — **28 из 28 серверных тестов**.
Один из них запускает весь демонстрационный набор из 12 HTTP-проверок.
В `reports/check-report.json` — отдельный фактический запуск этого набора, 12 из 12.
Не складывайте эти числа как независимые тесты.

В `reports/browser-components.json` — **25 из 25 компонентных проверок**,
включая ширины 320 и 390 пикселей. Снимки — в `previews/`.
**Это не полноценный браузерный E2E-тест:** браузеру в рабочем окружении недоступна
навигация по URL. DOM, CSS и модули проверялись в памяти браузера с транспортом к
настоящему локальному демосерверу. HTTPS, браузерные cookie/CSP/CORS и переходы
по реальным ссылкам в этой проверке не испытывались. Подробности — `QA.md`.
Обязательна самостоятельная проверка обычного запуска в командном Codespaces.

Число 12 — наш выбранный демонстрационный набор, **не число официальных требований**.
В исходном кейсе перечислены пять Must have. Отчёт доказывает только поведение
этого демосервера на этих сценариях, а не соблюдение всего ТЗ реальным магазином.

## Ограничения и что доделать команде

Нет реального AI и понимания произвольной спецификации: используется строгий формат
артикулов. Тест с посторонней командой проверяет парсер и разделение чтения/записи,
**не** устойчивость языковой модели к prompt injection.
Нет Excel/Word/PDF/JPEG, оплаты, аккаунтов магазина, реального оформления,
удаления/редактирования корзины, сохранения чата после перезагрузки,
реальных сертификатов и инженерной гарантии совместимости.

Количество целое, цены — целые тенге. Всё хранится в памяти одного процесса:
перезапуск очищает сессии и корзины. Атомарность/идемпотентность не испытаны между
несколькими процессами и после перезапуска. Наличие не резервируется между покупателями.

Для интеграции согласуйте `API.md`, подключите каталог и источник условий,
адаптер настоящей корзины/сессии, AI только с разрешёнными функциями чтения,
транзакции и хранение ключей идемпотентности в БД. Затем повторите тесты именно
на интегрированной версии. Ключи и Basic Auth должны остаться на backend.
Не загружайте в GitHub файл с выданными доступами или непубличную выгрузку каталога.

Сценарий демонстрации и распределение на троих — `DEMO.md`.
Короткий порядок замены старой папки — `START_HERE.md`.
